# 相続税申告 AIリアルタイム面談・必要資料管理システム（Phase 1）

営業担当者が相続人と面談するとき、パソコンのマイクで会話を取得し、
**Gemini でリアルタイムに文字起こし** → **Claude で事実を構造化** → **事務所のルールで必要資料を判定** し、
画面左側の確認事項・必要資料リストを数秒以内に更新するWebアプリです。

> 既存の `index.html`（相続管理アプリ）とは独立したアプリです。既存アプリには一切変更を加えていません。

| 確認事項 | 14カテゴリー・63項目。未確認／AI確認候補／確認済み／要追加確認／該当なし／矛盾あり | ✅ |
| 必要資料 | **ルールマスタで判定**（AIは資料を決めない）。重複追加なし。必要候補／必要確定／…／削除候補 | ✅ |
| 取りこぼし防止 | 未確認事項の管理、次の質問（最大3件）、面談終了時の警告、**面談後の全文再解析**、根拠発言の必須化 | ✅ |
| 訂正対応 | 「常陽銀行ではなく筑波銀行」→ 旧情報は撤回として履歴に残し、資料は削除候補に。**承認済み情報はAIが変更しない** | ✅ |
| 根拠リンク | 左の項目の「根拠」→ 右の発言へスクロール／右の発言クリック → 左の対応項目を強調 | ✅ |
| 資料依頼書 | 取得先・取得方法は資料マスタの登録内容のみ。ブラウザの印刷機能で PDF 保存 | ✅ |
| 管理画面 | ルールの編集・税理士承認、専門用語（カスタム語彙）、設定、費用・応答時間（P50/P95）、ユーザー権限 | ✅ |
| 費用管理 | Claude トークン・Gemini 音声時間を案件／面談／月／モデル別に記録。上限接近で管理者に通知、上限超過でAI解析のみ停止（発言は保存継続） | ✅ |
| デモ再生 | マイク・APIキーなしで架空面談を再生し、全体の流れを確認 | ✅ |

## 2. しくみ（Gemini と Claude の責務分離）

```
 ブラウザ（担当者のPC）                          サーバー（Cloud Functions / 東京リージョン）
 ┌──────────────────────┐   ①一時トークン要求   ┌────────────────────────────┐
 │ マイク → 16kHz PCM    │ ───────────────────▶ │ createTranscriptionSession │ ← Gemini APIキー（Secret Manager）
 │                      │ ◀─── 一時トークン ─── │ （同意・権限を確認）          │
 │ ②Gemini Live へ直接   │                      └────────────────────────────┘
 │   ストリーミング（遅延最小）                   ┌────────────────────────────┐
 │ ③暫定/確定テキスト表示 │ ④確定発言を保存 ───▶ │ Firestore（発言）             │
 │                      │ ⑤解析依頼（発言IDのみ）▶│ analyzeSegments             │ ← Claude APIキー（Secret Manager）
 │                      │                      │  ・Claude: 事実を構造化        │
 │ ⑦画面が自動更新 ◀──── Firestore 購読 ─────── │  ・統合: 根拠・訂正・承認保護   │
 └──────────────────────┘                      │  ・ルールエンジン: 必要資料判定 │
                                                └────────────────────────────┘
```

- **Gemini**: 音声 → 文字だけを担当。APIキーはブラウザに渡さず、サーバーが**1回限り・短時間の一時トークン**を発行します（モデル・語彙・設定もトークン側で固定）。
- **Claude**: 文字 → 事実（財産・人物・回答）の構造化だけを担当。必ず根拠の発言IDを付けさせ、根拠のない事実は登録しません。
- **ルールエンジン**（`shared/src/ruleEngine.ts`）: 事実 → 必要資料。AIに依存しない決定的な判定で、税理士が管理画面から変更できます。

詳しいデータ設計・画面設計は [docs/DESIGN.md](docs/DESIGN.md) を参照してください。

## 3. 実装時に確認した API 仕様

| 項目 | 内容 | 確認方法 |
|---|---|---|
| 音声認識モデル | `gemini-3.5-transcribe-live`（Live API / BidiGenerateContent） | Google公式SDK `@google/genai` 2.31.0 の型定義、Web検索 |
| 暫定テキスト | `serverContent.interimInputTranscription` | 同上 |
| 確定テキスト | `serverContent.inputTranscription`（`finished` で確定） | 同上 |
| カスタム語彙 | `inputAudioTranscription.customVocabulary`（文字列配列） | 同上 |
| 文字起こしモード | `VERBATIM`（既定・省略しない）／`SMART`（言い淀み除去）→ **VERBATIM を使用** | 同上 |
| 一時トークン | `authTokens.create`（v1alpha）、`liveConnectConstraints` で設定固定 | 同上 |
| セッション再開 | `sessionResumption`（`transparent: true` で未処理の音声位置を通知） | 同上 |
| 音声形式 | 16bit PCM / 16kHz / モノラル | 同上・Web検索 |
| Claude | `claude-sonnet-5-5`（環境変数で変更可）、Structured Outputs（`output_config.format`）、プロンプトキャッシュ | Anthropic SDK 1.3.0・公式ドキュメント |

> ⚠️ **注意（必ずお読みください）**
> - この開発環境からは Google の公式ドキュメントサイト（ai.google.dev 等）に接続できなかったため、Gemini の仕様は **Google公式SDKの型定義** と検索結果で確認しました。
>   Live 文字起こしは公開プレビュー段階の情報があり、**1セッション約10分の上限**・**話者分離（diarization）の対応状況**などは導入前に公式ドキュメントで再確認してください。
>   話者分離は未確認のため既定で **オフ**（`GEMINI_DIARIZATION=false`）にし、話者は画面上で修正できるようにしています。
> - **実際の Gemini・Claude API には接続してテストしていません**（APIキーがないため）。APIキー以外の部分（画面・保存・解析の流れ・ルール判定・権限）はエミュレーターで動作確認済みです。
>   キーを設定したら「6. 動作テスト」の手順で実APIの確認と精度評価を行ってください。

## 4. パソコンで試す（APIキー不要・ローカル）

Firebase の「エミュレーター」（パソコン内で動く Firebase の模擬環境）と、デモ再生を使って、本番と同じ流れを確認できます。
AI解析は簡易版（キーワード判定）になるので精度は参考になりませんが、画面とデータの動きはすべて確認できます。

### 準備（初回のみ）
1. **Node.js 22** をインストール（https://nodejs.org/ の LTS 版）
2. **Java 21 以上** をインストール（Firestore エミュレーターに必要。例: https://adoptium.net/ ）
3. このフォルダで依存パッケージをインストール
   ```bash
   cd mendan
   npm install
   ```
4. APIキーの空ファイルを作成（ローカル専用・Git には含まれません）
   ```bash
   printf "ANTHROPIC_API_KEY=unset\nGEMINI_API_KEY=unset\n" > functions/.secret.local
   ```

### 起動（ターミナルを2つ使います）
```bash
# ターミナル1: Firebase エミュレーターを起動（「All emulators ready!」と出るまで待つ）
npm run emulators:clean

# ターミナル2: 画面を起動
npm run dev
```
ブラウザ（Chrome 推奨）で http://127.0.0.1:5173 を開きます。

### 操作の流れ
1. ログイン画面の「開発用ログイン」で `admin@example.com` のままログイン（管理者になります）
2. 「新しい相続案件」に案件名・被相続人名・相続開始日を入れて「案件を作成」
3. 案件画面で「録音に同意」「AIによる文字起こし・解析に同意」にチェック →「同意状況を記録」
4. 「初回面談を開始」→ 面談画面で **「デモ再生」** を押す
5. 右側に会話が流れ、左側の「必要資料」タブに資料が追加されていくことを確認します
   （「常陽銀行→筑波銀行」の訂正で、常陽銀行の資料が「削除候補」になります）
6. 「面談終了」→ 未確認事項の警告 →「このまま終了する」→ 全文の再解析
7. 「資料依頼書」→「印刷 / PDFに保存」

## 5. 本番環境の準備（管理者の作業）

> ここから先は **Google Cloud の課金設定・有料サービス・本番公開** を含みます。
> 指示書のとおり、**事前に管理者の承認を得てから** 実施してください（開発側ではデプロイしていません）。

### 5-1. Firebase プロジェクト
1. https://console.firebase.google.com/ で「プロジェクトを追加」（既存の事務所用 Google Cloud プロジェクトを選んでも構いません）
2. 料金プランを **Blaze（従量課金）** に変更（Cloud Functions と Secret Manager に必要）
   - 予算アラートを設定しておくことをおすすめします（Google Cloud コンソール →「お支払い」→「予算とアラート」）
3. 左メニューで次を有効化します
   - **Authentication** →「始める」→ ログイン方法で **Google** を有効化
     - 「設定」→「承認済みドメイン」に本番URL（例: `xxx.web.app`）があることを確認
   - **Firestore Database** →「データベースを作成」→ ロケーション **asia-northeast1（東京）** →「本番環境モード」
   - **Storage** →「始める」→ ロケーション **asia-northeast1**（録音データの保存先）
4. 「プロジェクトの設定」→「マイアプリ」→ ウェブアプリ（`</>`）を追加し、表示された値を控えます

### 5-2. APIキーの取得
- **Claude**: https://console.anthropic.com/ →「API Keys」でキーを作成
  - 実データを使う前に、Anthropic のデータ利用条件（商用規約・データ保持）を確認してください
- **Gemini**: https://aistudio.google.com/ →「Get API key」で、上と同じ Google Cloud プロジェクトにキーを作成
  - 無料枠では送信データがサービス改善に使われる場合があります。**実データは有料（課金）設定のキーで**、データ利用条件を確認のうえ使用してください

### 5-3. コマンドでの設定とデプロイ
ここではパソコンのターミナルで操作します。

```bash
# (1) Firebase CLI にログイン（ブラウザが開きます）
npx firebase login

# (2) このフォルダを Firebase プロジェクトに紐づけ（「プロジェクトID」は 5-1 のもの）
cd mendan
npx firebase use --add        # 一覧から選び、別名は「prod」などでOK

# (3) APIキーを Secret Manager に登録（入力を求められたらキーを貼り付け。画面には表示されません）
npx firebase functions:secrets:set ANTHROPIC_API_KEY
npx firebase functions:secrets:set GEMINI_API_KEY

# (4) サーバーの設定ファイルを作成して編集
cp functions/.env.example functions/.env
#   → functions/.env を開き、ALLOWED_EMAIL_DOMAINS（事務所のドメイン）と ADMIN_EMAILS（管理者）を書き換える

# (5) 画面の設定ファイルを作成して編集
cp web/.env.example web/.env.production
#   → 5-1 の 4 で控えた値を VITE_FIREBASE_... に貼り付け、VITE_ALLOWED_DOMAIN にドメインを入れる

# (6) ビルドしてデプロイ（セキュリティルール・関数・画面をまとめて公開）
npm run build
npx firebase deploy
```

デプロイが終わると `https://<プロジェクトID>.web.app` で利用できます。
最初に `ADMIN_EMAILS` のアカウントでログインすると管理者になります。管理画面 →「専門用語」→「初期語彙を登録」を一度押してください。

### 5-4. 更新を反映するとき
コードを変更したら、同じく `cd mendan` → `npm run build` → `npx firebase deploy` です。
画面だけなら `npx firebase deploy --only hosting`、サーバーだけなら `npx firebase deploy --only functions` でも反映できます。

### 5-5. 応答速度を上げたい場合（任意・追加費用あり）
Cloud Functions は使われていないと停止し、最初の呼び出しが数秒遅くなります（コールドスタート）。
面談中の遅延を避けるには `functions/src/analyze.ts` の `onCall({...})` に `minInstances: 1` を加えると常時1台待機します（月数千円程度の追加費用。承認のうえ設定してください）。

| コマンド | 内容 | APIキー |
|---|---|---|
| `npm test` | ルールエンジン・統合ロジックの単体テスト（訂正・承認保護・根拠必須・順序逆転・重複防止・不動産の未確認項目 など15件） | 不要 |
| `npm run test:integration` | エミュレーター上で関数・セキュリティルールを結合テスト（権限・同意・二重保存拒否・承認保護 など24項目）※要 `npm run emulators:clean` | 不要 |
| `node scripts/e2e-demo.cjs` | ブラウザでログイン〜デモ面談〜資料依頼書までを自動操作（18項目）※要 エミュレーター＋`npm run dev` | 不要 |
| `npm run eval` | 指示書16の10シナリオで精度指標を計算（簡易解析器） | 不要 |
| `ANTHROPIC_API_KEY=... npm run eval -- --mode=claude` | **同じ10シナリオを実際の Claude で評価**（抽出再現率・資料再現率・不要資料・訂正・根拠対応率・P50/P95）。結果は `eval/results/` | 必要（数十回の呼び出し・料金発生） |

**今回の実行結果（この開発環境）**: 単体テスト 15/15、結合テスト 24/24、ブラウザ通しテスト 18/18 成功。
精度評価は簡易解析器のみ実行（再現率 約68%。キーワード判定のため参考値で、Claude の精度ではありません）。
**Claude による精度評価（目標: 重要財産・必要資料の再現率 99% 以上）は APIキー設定後に実施が必要です。**

実際のマイクでの確認（指示書19の最終確認）:
1. 5章のとおり本番（またはステージング）環境を用意
2. 面談画面で「● 録音開始」→ マイクを許可 → 架空の相続面談を話す
3. 右側の文字起こしに応じて左側の必要資料が更新されること、ヘッダーの「反映 ○秒」、管理画面「費用・性能」の P50/P95 を確認

## 7. 費用の目安（実測前の概算）

| 項目 | 前提 | 概算 |
|---|---|---|
| Claude（リアルタイム解析） | `claude-sonnet-5-5`（入力 $2・出力 $10 / 100万トークン）。1回あたり 指示文約5千トークン（キャッシュで1/10）＋案件情報・発言 約3千＋出力 約1千 | 1回 約2円、1時間の面談（約200〜300回）で **約400〜700円** |
| Claude（面談後の再解析） | 全文を1回、effort=high | 1回 約20〜40円 |
| Gemini（文字起こし） | 第三者サイト掲載の単価 約$0.54/時間（**未確認・公式料金表で確認が必要**） | 1時間 約80円 |

費用削減のため、①指示文のキャッシュ、②全文を毎回送らない、③同じ発言の再解析をしない、④短い発言はまとめる、を行っていますが、**解析回数を減らして取りこぼしが増える設計にはしていません**。

| 事項 | 理由 | 影響 |

| Google Drive 連携・スキャン資料のAI照合・催促管理（Phase 3〜4） | 指示書の順序どおり Phase 1 の完成を優先 | 資料の回収管理は画面の状態変更（依頼済み・提出済み等）のみ。資料ごとの催促欄はデータ構造だけ用意 |

## 9. セキュリティ

- Gemini・Claude の APIキーは **Secret Manager** に保存し、ブラウザには一切渡しません（Gemini は1回限り・2分以内に接続・30分で失効する一時トークン）
- ログインは許可した Google Workspace ドメインのみ（`ensureUser` で確認し、`users/{uid}.active` がないと Firestore も関数も使えません）
- **案件単位のアクセス権限**（管理者は全案件、担当者・閲覧者はメンバーの案件のみ）を Firestore／Storage のセキュリティルールで強制
- 抽出情報・確認事項・必要資料の変更は**すべてサーバー経由**で、操作履歴（AuditLogs）と各データの修正履歴を保存
- ブラウザから直接書けるのは「確定した発言の新規保存（上書き・削除不可）」と計測値・録音ファイルの登録のみ
- サーバーのログに会話内容・顧客名は出力しません（IDと件数のみ）
- 録音データは設定した保存期間（初期値365日）を過ぎると毎日自動削除
- 外部AIに送るのは「新しい発言・直近の会話・案件の抽出済み情報」のみ（会話全文は面談後の再解析時のみ）
